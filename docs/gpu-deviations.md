# GPU devices: deviations from real hardware

Where the emulated VMware SVGA II and virtio-gpu ([gpu-devices.md](gpu-devices.md))
do not behave like the hardware they model, because WebGPU lacks something or
because something is not done yet. The rule is the one the D3D8/D3D9 proxies
follow: a capability is declared only when code backs it; what WebGPU cannot
do is emulated and listed here rather than hidden. How the commands reach the
GPU is in [Architecture](gpu-devices.md#architecture) and
[GX](gpu-devices.md#gx); larger deferred work, with the options known, is in
[Not done and deferred](gpu-devices.md#not-done-and-deferred).

Legacy 3D (`vgpu9`, and D3D9 applications on Windows at every 3D level) runs
on the D9WG executor that the D3D8 and D3D9 proxies share. What that executor
emulates (point sprites, user clip planes, `BORDER` addressing, D3D9's
half-pixel offset) is documented with the proxies, in `d3d8proxy/README.md`
and `d3d9proxy/README.md` of
[retro-gaming-site/glbridge](https://github.com/speedyHKjournalist/retro-gaming-site/tree/main/glbridge),
and is not repeated here. The tables below cover the devices, GX (SVGA DX and
virgl) and Venus.

## Emulated

| Id | Topic | How it is done | Difference from hardware |
| --- | --- | --- | --- |
| G-01 | Geometry shaders | The vertex shader runs as compute into records, the geometry shader as compute over them, then a draw of what it emitted; GS instancing | Room for `maxvertexcount` vertices per primitive is reserved; only stream 0 is drawn; not for indirect draws (warned, not drawn) |
| G-02 | Stream output, `DrawAuto` | A compute pass after the vertex or geometry stage writes the targets and their filled sizes; `DrawAuto` reads the size; the statistics queries count primitives written and needed, and overflows | Stream 0 only; not for indirect draws, adjacency topologies or after tessellation |
| G-03 | Tessellation | Hull shader per patch in compute (control point, fork and join phases), the D3D11 reference tessellator in WGSL, domain shader per point, an indirect draw | No geometry shader or stream output after tessellation; not for indirect draws (warned, not drawn) |
| G-04 | MSAA (4x, 8x) | Supersampling: a 4x surface is a 2W×2H texture, 8x is 4W×2H; sample index from the position; sample mask, oMask and alpha-to-coverage by discard; resolves average the block. SVGA declares 4x from `dx10` (for the formats its table marks; from `dx10.1` for every target format) and 8x from `dx11`, never 2x (`SVGA3D_DEVCAP_MULTISAMPLE_2X` is 0); virgl declares at most 4 samples | Samples lie on a grid, not D3D's standard pattern, so edge coverage differs slightly (virgl declares the grid's positions, the centres of a 2×2 block) |
| G-08 | Depth formats | D24 formats are WebGPU's `depth24plus(-stencil8)`; uploads of depth go through a draw that writes `frag_depth` (WebGPU copies data only into `depth16unorm` and stencil aspects); readbacks of `depth16unorm` and `depth32float` are depth-only copies | An upload of depth costs a draw; other depth formats and stencil do not read back (see "Depth and multisampled surfaces" under Not done) |
| G-09 | Formats WebGPU lacks | Stored wider and converted on upload and readback: 565, 1555, 4444, RGB32, UNORM16/SNORM16, A8, L8, L8A8, SNORM8 render targets, X8 formats | Wider storage; precision of blending into converted formats can differ |
| G-11 | Typed UAVs | Storage textures, the format taken from the bound view; read-write access only for R32 formats; atomics on buffer UAVs (raw, structured, typed) and on group-shared memory are WGSL atomics | Typed loads of other formats are not offered; atomics on typed texture UAVs (virgl's image atomics too) are not done: warned, and the returning forms give 0 |
| G-12 | Doubles (SM5, GL 4.x) | Declared; computed as f32 (WGSL has no f64), including VMware's `DFRC` and `DRSQ` | Range and precision are float's |
| G-17 | Provoking vertex (GL: the last) | Draws with flat varyings get their vertices reordered, the last first (a rotation, so winding is kept): fixed orders without indices, a compute pass over the indices with them (restarts included); triangle fans (which D3D10 lacks but Mesa's svga sends) are drawn as lists this way | Indirect draws keep WebGPU's first vertex; triangle fans are not drawn (warned) when indirect or with a geometry shader, stream output, tessellation or pulled vertices (G-40) |
| G-18 | `eval_*` | The attribute at the fragment (each fragment is a sample when supersampled) | Not at the requested offset |
| G-25 | Format views across a typeless family | A view of another format of the same texel layout (R32G32B32A32_UINT of a FLOAT texture) uses an alias texture of that format; the contents follow the format used last, copied raw through a buffer | A copy each time a surface switches family |
| G-26 | Integer textures sampled with `sample` (GL `texture()` on an integer sampler) | The texel under the coordinates, by a load clamped to the level's edges | The sampler's wrap mode is not applied |
| G-27 | Comparison samplers declared "default" (Mesa's svga declares every sampler so) | The sampler's WGSL type comes from its use; a sampler used both ways gets a comparison twin | None |
| G-28 | Clip distances | WebGPU's `clip-distances` on the vertex stage; virgl's GL clip distances are varyings, and the fragment shader discards where one that the rasterizer state enables is below zero | Not when the last stage before the rasterizer is a geometry or domain shader (warned) |
| G-29 | Integer clears with float values | Mesa's svga sends a UINT target's values as its signed ints (`-16.0` for `0xFFFFFFF0`): negative values wrap, the rest saturate as D3D converts | None for Mesa; D3D applications get D3D's saturation |
| G-30 | Host visible memory (virtio-gpu `virgl43-hostmem`) | The guest's writes are uploaded by page before each `SUBMIT_3D`; mapped buffers the GPU wrote are read back whole before the submit's fence | Page granularity; the whole buffer is read back after each submit that writes it |
| G-31 | 3D scanout | 3D results reach the screen by readback into the device's picture (only the dirty rectangle's columns from GX) | One readback per present |
| G-32 | SVGA video overlay | Drawn over the device's picture like the cursor (each unit a patch of the desktop with the video where it shows); BT.601 video range, nearest-neighbour scaling | No filtering when scaled |
| G-33 | Venus host visible memory | A GPU buffer, mirrored in BAR4 while the guest maps it: written pages go up before each submission, the byte ranges the GPU writes (copies, fills, updates, image to buffer copies, the whole of each storage buffer a draw or dispatch binds) come back before its fence and semaphores signal | Reads back whole bound storage ranges; a guest write racing a GPU write to the same bytes loses (Vulkan leaves it undefined) |
| G-34 | Vulkan push constants | A read-only storage buffer at a group after the sets (or binding 998 of the last group), written per draw that changed them | One more storage buffer per stage |
| G-35 | Combined image samplers | Split into an image and a sampler before naga reads the SPIR-V (Vulkan binding b is WGSL binding 2b, its sampler 2b + 1); a descriptor array is split first, a binding an element (G-49) | Arrays indexed other than by constants are not done |
| G-36 | Vulkan's clip space | naga flips Y of the position; viewports and scissors are WebGPU's, clamped into the target. A viewport of a negative height (`VK_KHR_maintenance1`, ANGLE's way of drawing upside down) draws with a variant of the pipeline whose vertex shader keeps Vulkan's Y (naga without `adjust_coordinate_space`) in the viewport flipped back | One more pipeline (and bind groups) for each pipeline drawn with a flipped viewport |
| G-37 | Vulkan queries | Occlusion queries are WebGPU's; a render pass names one pool (the first one begun in it); timestamps are the time the device writes the batch (ns); a pool's results come back before the fence | Not precise (`occlusionQueryPrecise` is off: WebGPU promises zero or not, and Chrome on Metal answers 1); occlusion queries outside of render passes, or of a second pool in one, are 0; pipeline statistics are 0 |
| G-38 | Venus WSI | Mesa's software WSI (no dma-buf): every present copies the image into a host visible buffer that the device reads back, then the CPU copies it to `wl_shm` | A frame's pixels cross from the GPU to the guest and back to the compositor |
| G-39 | Venus snapshots | Renderer objects are made again from their creation commands; memories and images get the contents read back before the save | Multisampled images, 24-bit depth and 32-bit depth come back without their contents (WebGPU copies none of them, or writes no 32-bit depth); depth/stencil resolves are not done (`VK_KHR_depth_stencil_resolve` says sample zero) |
| G-40 | Vertex input WebGPU cannot fetch | When an input layout has a format without a WebGPU vertex format (`R10G10B10A2_UINT`, `R11G11B10_FLOAT`, `B8G8R8X8_UNORM`: the `pull:` entries of `svga_dx_formats.js`), an instance step rate above 1, an element offset not aligned to its size (up to 4 bytes), or a stride that is not a multiple of 4, is smaller than its elements or is above 2048, the vertex shader runs as compute and reads its vertices from the bound buffers itself, and its records are drawn | A compute pass more per draw; not for indirect draws (warned, not drawn) or triangle fans (G-17); with stream output only the streamed vertices are pulled, so such a draw is not rasterized right |
| G-41 | DX queries (SVGA DX; virgl's occlusion queries and timestamps) | An occlusion query (`OCCLUSION`, `OCCLUSION64`, `OCCLUSIONPREDICATE`) is a WebGPU occlusion query in each render pass while it is active, summed when it ends; a predicate answers 0 or 1. A timestamp is `performance.now()` in ns; `TIMESTAMP_DISJOINT` answers 1 GHz, not disjoint | Occlusion counts are not exact sample counts (WebGPU promises zero or not; Chrome on Metal answers 1); timestamps are when GX reaches the query, not GPU time |
| G-42 | virgl's primitive queries | `PRIMITIVES_GENERATED` and `PRIMITIVES_EMITTED` are counted by the device from each draw's primitive mode, vertex count and instance count, before rasterizer discard; `GPU_FINISHED` answers 1 | Both give the same number, the draw's own primitives: what geometry shaders and tessellation make, indirect draws and stream output overflow are not counted. `TIMESTAMP_DISJOINT`, `TIME_ELAPSED` (GL's time elapsed queries), and stream output statistics and overflow predicates answer 0 |
| G-43 | Venus: Android's gralloc buffers | A dma-buf image (`VK_EXT_image_drm_format_modifier`, the linear modifier only) bound to memory imported from its virtio-gpu resource (`VkImportMemoryResourceInfoMESA`) borrows the resource's GX surface as its texture (`VX.TEXTURE_IMPORT`); after each Venus submission the GPU's copy of every imported resource is the newer one, so scanout and `TRANSFER_FROM_HOST` read it back. `VK_EXT_external_memory_dma_buf` is not offered (nothing becomes a dma-buf, and Mesa's venus on Linux would take swapchain images for dma-bufs, G-38); the Android driver imports without it (`tools/a64_venus/venus-android.patch`) | Every imported resource counts as written by every submission |
| G-44 | Passes and pipelines without attachments; rasterizer discard | WebGPU needs an attachment: such a pass gets a placeholder `r8unorm` attachment of the render area, and such a pipeline a target for it that it does not write, single-sampled. Rasterizer discard is a fragment stage that writes nothing (with the pass's targets, depth and stencil writes off) | A pipeline without attachments rasterizes with one sample whatever its sample count; under rasterizer discard fragments still run, and occlusion queries count them |
| G-45 | Venus transform feedback (`VK_EXT_transform_feedback`) | A capturing draw first runs as a compute pass made from its vertex shader (naga's `xfb` module: the vertex entry point copied, its outputs with XFB offsets written to storage buffers, its inputs pulled from the bound vertex buffers by their formats), into scratch buffers then copied to the bound ranges; the render pass ends for it and begins again with its attachments loaded, then the draw runs as usual. The written counts, counter buffers and `TRANSFORM_FEEDBACK_STREAM` queries are counted by the device from each draw | Stream 0 only (no `geometryStreams`); point, line and triangle lists (strips and fans capture nothing, warned); indexed and indirect draws capture nothing (GL ES 3.0 has none; warned); occlusion queries in a pass do not go on across a capture; a pass that discards its attachments loses what it drew before a capture |
| G-46 | Uniform buffers past WebGPU's 12 a stage | Venus offers 14 (`maxPerStageDescriptorUniformBuffers`: GL ES 3.0's 12 besides ANGLE's default uniforms); a pipeline layout with more than 12 in a stage has the rest bound as read-only storage buffers, naga rewriting their bindings (`storage_uniforms`) | They count against WebGPU's 10 storage buffers a stage (Venus offers 8) |
| G-47 | Venus varyings, 24-bit depth transfers | 68 vertex output and fragment input components (17 of WebGPU's inter-stage variables, one past its default: ANGLE keeps 4 to capture `gl_Position`); `D24_UNORM_S8_UINT` and `X8_D24_UNORM_PACK32` have the transfer features (ANGLE asks them of a window's depth-stencil image): copies between images and of the stencil aspect are WebGPU's | A host with only 16 inter-stage variables fails a pipeline that uses all 17; copies of 24-bit depth to or from buffers are skipped (warned) |
| G-48 | Venus: dynamic stencil masks, point size, NaN tests, fans, indexed strips | `vkCmdSetStencilCompareMask` and `vkCmdSetStencilWriteMask` (ANGLE sets them per draw): a variant of the pipeline per pair of masks, made at the first draw with it; a vertex shader's `gl_PointSize` is dropped (WebGPU draws one-pixel points; a capture keeps it, G-45); `OpIsNan` and `OpIsInf` are bit tests of the float's bits (WGSL has neither); a triangle fan is a list through an index buffer of Vulkan's (i + 1, i + 2, 0); an indexed strip's pipeline gets a variant with the strip index format (WebGPU's rule) | Points of one pixel; indexed strips always restart at the index type's largest value (WebGPU's), even without `primitiveRestartEnable` |
| G-49 | Venus: SPIR-V naga does not read or WGSL cannot say (ANGLE's GLSL ES 3.0) | Rewritten around naga (`src/browser/glbridge/vx/naga/src`): std140 matrices that are row-major or whose stride is not WGSL's, and std140 arrays of scalars and 2-component vectors (16 bytes apart; WGSL's are 4 and 8), become arrays of `vec4` read column by column or element by element (`layout.rs`); matrix, array and struct varyings and fragment outputs become one location a leaf, and a fragment output narrower than its target is padded with 0 (alpha 1) (`io.rs`); `texture()` on an integer sampler is a fetch of the texel under the coordinates, clamped to the level, at the level an explicit lod names or, in a fragment shader, the one the nearest mip filter takes from the coordinates' derivatives and the bias (`intsample.rs`, as G-26), and on an integer cube one from the face the direction selects, the cube bound as a 2D array of its faces (`cubes.rs`); `textureSize` of an array texture gets its layer count (`layers.rs`); `outerProduct` is a matrix of columns, and modf's and frexp's result structs are declared (`math.rs`); a switch case that falls through takes a copy of the next case's statements (`switches.rs`); a descriptor array (`uniform B { } b[N]`, `uniform sampler2D s[N]`, N up to 16, bindings up to 19) is one binding an element the shader uses, element e > 0 at WGSL binding 300 + 2 (16b + e), its sampler one more (`blockarrays.rs`); naga's module is compacted before it is written (its writer writes every type). Each buffer binding's least size (its WGSL type's) is bound even when the guest's range is shorter (std140's padding at a block's end), from the memory after it | Integer samplers ignore the wrap mode and filter (G-26); arrays indexed other than by constants keep naga's error; a range short of its block at the very end of its memory is bound short (warned, WebGPU refuses it) |
| G-50 | Venus: framebuffer fetch, depth writes and ranges, aliasing, unaligned copies | Input attachments (ANGLE's framebuffer fetch, and its emulation of `KHR_blend_equation_advanced`) are textures read at `gl_FragCoord.xy` plus the offset (`subpass.rs`); a texture that is an attachment of the pass drawing is read from a copy made before the draw (the pass ends, the copy, the pass resumes with its attachments loaded). A fragment shader's depth in a pipeline without a depth attachment is dropped (WebGPU refuses it; Vulkan ignores it). A viewport whose minDepth is above its maxDepth (`glDepthRangef(1, 0)`) draws with a vertex variant writing `w - z` and the depths swapped (`depth.rs`). `MIN` and `MAX` blending use the factor one (WebGPU's rule; Vulkan ignores the factors). A dispatch that writes a buffer it also binds read-only reads a copy of it. Buffer and buffer-image copies of offsets or rows not 4-byte aligned go through a compute pass that rewrites the dwords | A copy of the attachment for each draw that reads it; a dispatch's read-only bindings of a buffer it writes see the buffer as it was before the dispatch |
| G-51 | Venus: GL's provoking vertex (`VK_EXT_provoking_vertex`) | ANGLE asks every pipeline for the last vertex; a draw of a pipeline whose vertex shader has flat outputs is drawn as a list with each primitive's vertices rotated, the last first (triangles keep their winding): without indices through an index buffer made once per count, with indices through a compute pass that rewrites them (restarts included) between two halves of the render pass, the draw then indirect. Indexed triangle fans are drawn so too | Indirect draws keep WebGPU's first vertex (warned); a reordered indexed draw ends and resumes its pass (occlusion queries, as G-45) |
| G-52 | Venus: vertex input WebGPU cannot take | A pipeline with more than 8 vertex bindings (ANGLE gives each attribute one, up to 16), a stride not in dwords or above 2048, or an attribute not aligned to its size, and a draw whose buffer is bound at an offset not in dwords, has its attributes repacked at the draw (a compute pass between two halves of the render pass) into up to three buffers: the constants (stride 0), the vertices and the instances, each attribute a field; the pipeline (or its variant) takes those | The draw's vertices from 0 to its last are repacked, for indexed and indirect draws as many as the bound buffers have (up to 2^20); the pass ends and resumes for it |
| G-53 | Venus: blits of 3D images, pipelines without a fragment shader | A blit from or into a 3D image draws each destination slice (`depthSlice`) from the source's depth its middle maps to; a pipeline with no fragment shader (a depth-only draw) gets one that writes nothing for the pass's attachments | Blits into depth and formats not renderable are not offered (`BLIT_DST` is for renderable color formats) |
| G-54 | Venus: 16-bit packed formats (`R5G6B5`, `R5G5B5A1`, `A1R5G5B5`) | Vulkan's required color formats, and GL ES 3.0's RGB565 and RGB5_A1, which ANGLE puts on nothing else: textures of `rgba8unorm`; copies through buffers unpack and pack the 16-bit texels in a compute pass; draws, clears and blits into `R5G6B5` leave alpha at 1 (its write mask, clear values), so that sampling it reads 1 | Draws and blending at 8 bits a channel until the texels are copied out; copies between them and other formats of 16 bits are not done (warned) |
| G-55 | Venus: view swizzles (`VkComponentMapping`) | WebGPU's views have none (ANGLE's GL_ALPHA, GL_LUMINANCE and GL_LUMINANCE_ALPHA are R8 and RG8 swizzled; GL ES 3.0 has texture swizzles): a draw or dispatch sampling a swizzled view samples a copy of it of four components (rgba8unorm, its sRGB twin, rgba16float, rgba32float or rgba32uint/sint), drawn swizzled, mip by mip and layer by layer, again whenever its texture was written since (copies, clears, blits, resolves, passes it was attached to, storage bindings, snapshots; imported textures every time) | A copy per swizzled view; depth, stencil and multisampled views are bound unswizzled (warned) |
| G-56 | Venus: stencil of each face, depth bias, culling both faces | WebGPU has one stencil reference and one pair of masks for both faces: a draw whose faces' differ (`glStencilFuncSeparate`, `glStencilMaskSeparate`) is drawn twice, each face with the other culled. The dynamic depth bias (`vkCmdSetDepthBias`, GL's `glPolygonOffset`) is a variant of the pipeline per bias (WebGPU's is the pipeline's, for triangles only). Culling both faces draws no triangles. `CONSTANT_ALPHA` blend factors (WebGPU's constant is the color's for color) get the constant's alpha in all four components | A draw with faces of different stencil state costs two; a pipeline blending with both the constant's color and its alpha is drawn with its color (warned) |
| G-57 | Venus: depth sampled as a float texture, 32-bit depth with stencil, unbound vertex buffers | A depth view bound where the shader samples a float texture (GL's `sampler2D` of a depth texture; WebGPU binds depth as depth or unfilterable float only) is read from a copy of (d, 0, 0, 1) in `r32float` (`r16float` on a device that filters no 32-bit floats), made again when the depth is written (as G-55). `D32_SFLOAT_S8_UINT` (GL ES 3.0's DEPTH32F_STENCIL8) is WebGPU's optional `depth32float-stencil8`, `depth24plus-stencil8` on a device without it. A vertex binding the pipeline reads with nothing bound reads zeros (warned) | A copy per depth texture sampled so, each time it is written; 24 bits of depth for DEPTH32F_STENCIL8 on devices without the feature |

## Not done

| Topic | State |
| --- | --- |
| MSI and MSI-X | Neither device has the capabilities; both interrupt through INTx (pin A), which vmwgfx and viogpudo use. viogpudo still programs an MSI-X configuration vector and gives up when it does not read back, so virtio-vga keeps the vector values written (`qemu_compatible`) |
| SVGA fence goals | A FIFO fence that passes writes `SVGA_FIFO_FENCE` and raises `SVGA_IRQFLAG_ANY_FENCE`; a MOB fence raises `SVGA_IRQFLAG_MOB_FENCE`. `SVGA_FIFO_FENCE_GOAL` and `SVGA_REG_FENCE_GOAL` are not read, and `SVGA_IRQFLAG_FENCE_GOAL` and `SVGA_IRQFLAG_REG_FENCE_GOAL` are never raised: a driver that unmasks only a goal interrupt gets none |
| SVGA command buffer prepend | `SVGA_REG_CMD_PREPEND_LOW` and `_HIGH` are kept (read back, saved), but the commands they point to are not run |
| SVGA registers of later hardware | The CURSOR4 registers (`SVGA_CAP2_EXTRA_REGS`) and dirty tracking (`SVGA_CAP2_DIRTY_TRACKING_REG`): not declared at any level, not implemented |
| SVGA commands | Logged once and skipped: `LOGICOPS_*` (GDI acceleration); `PRESENT_READBACK` and `SCREEN_DMA`; the guest-backed VGPU9 draw commands `SET_VERTEX_STREAMS`, `SET_VERTEX_DECLS`, `SET_VERTEX_DIVISORS`, `DRAW` and `DRAW_INDEXED` (`DRAW_PRIMITIVES` works at every 3D level); `INTRA_SURFACE_COPY`, `WHOLE_SURFACE_COPY`, `SCREEN_COPY` and `SURFACE_STRETCHBLT_NON_MS_TO_MS` (`SVGA_CAP2_INTRA_SURFACE_COPY` and `SVGA_CAP2_NON_MS_TO_MS_STRETCHBLT` are not declared). GX does not run `DX_TRANSFER_TO_BUFFER` (warned) |
| SVGA resolution following the page | Not done: VMware does it through VMware Tools' service in the guest (vmtoolsd, `Resolution_Set` over a TCLO channel), which the backdoor does not have; virtio-gpu follows `V86.set_display_size` |
| Surfaces shared by legacy 3D and DX | Textures move between D9WG and GX on the GPU. A buffer whose newest contents are in GX is not given to legacy 3D, as its bytes would first have to come back from the GPU: the legacy draw gets no buffer (warned). Multisampled and depth surfaces are not moved either (warned) |
| Depth and multisampled surfaces | SVGA reads back neither: legacy `SURFACE_DMA` into a depth surface is skipped (warned), out of one silently; `READBACK_GB_IMAGE`, `READBACK_GB_SURFACE` and `DX_READBACK_SUBRESOURCE` leave the MOB as it was. In a snapshot, legacy ones come back cleared and GPU-newer guest-backed ones with their MOB's older contents. GX reads back only `depth16unorm` and `depth32float` surfaces that are not multisampled, so virgl snapshots bring multisampled resources and the other depth formats (24-bit depth, depth-stencil) back zeroed. GX does not blit (stretches, format conversions, `DX_PRESENTBLT`) or resolve depth surfaces, copy between multisampled surfaces of different formats, or upload nonzero data into multisampled ones (all warned) |
| NV12, YUY2 and `R10G10B10_XR_BIAS_A2_UNORM` surfaces | Declared from `dx10.1`, as supported but neither sampled nor rendered, because VMware's driver wants them before it offers feature level 10_1 on Direct3D 11.1. They are made and copied, never sampled or drawn into; NV12 and YUY2 surfaces stay in guest memory. (Overlay video: G-32) |
| Predication and conditional rendering | `DX_SET_PREDICATION` (and virgl's `SET_RENDER_CONDITION`, which becomes it) is kept in the context state, the DX context MOB and snapshots, but GX never evaluates it: predicated draws and `DX_PRED_*` copies always run. virgl declares `conditional_render` (and `conditional_render_inverted` at `virgl43`), so GL's conditional rendering is offered but not honoured |
| Pipeline statistics queries | Answered 0 (SVGA DX, virgl; Venus does not offer them) |
| Geometry shader streams 1–3 | Not drawn |
| Layered rendering, viewport arrays | Only viewport 0 and scissor 0 are used (virgl's `SET_VIEWPORT_STATE` keeps the first, although `virgl43` declares 16 viewports). The render target array index and viewport index a shader writes are ignored, and a render target view is drawn at its first layer. In pixel shaders, `SV_PrimitiveID`, `SV_RenderTargetArrayIndex` and `SV_ViewportArrayIndex` read 0 |
| Wireframe and point fill | Drawn solid (warned): D3D's `FILL_WIREFRAME`, GL's `glPolygonMode` through virgl |
| Border and mirror-once addressing | D3D's `BORDER` and GL's `CLAMP_TO_BORDER` (through virgl) sample as clamp to edge, without the border color; `MIRROR_ONCE` samples as mirror repeat |
| Sampler LOD bias, `DX_SET_MIN_LOD` | The sampler state's mip LOD bias (D3D's `MipLODBias`; GL's `GL_TEXTURE_LOD_BIAS` through virgl, which declares `max_texture_lod_bias` 16) is not applied, as WebGPU samplers have none; a bias in the shader (`sample_b`) is. `DX_SET_MIN_LOD`, a resource's minimum LOD clamp, is ignored |
| Shader translation | UAVs in vertex shaders (WebGPU's vertex stage cannot write storage; warned). Signed atomic minimum and maximum (`atomic_imin`, `atomic_imax`, `imm_atomic_imin`, `imm_atomic_imax`; virgl's `ATOMIMIN`, `ATOMIMAX`) are done unsigned, so negative values compare wrong. SM5 dynamic linkage (class instances, `interface_call`): `DX_SET_SHADER_IFACE` and `DX_BIND_SHADER_IFACE` are accepted without effect, and a shader that calls through an interface does not translate |
| Bindings beyond the adapter's limits | The WebGPU device is requested with the adapter's maximum of each limit D3D10/11 depends on (render target bytes, varyings, sampled textures, samplers, storage and uniform buffers, vertex buffers and attributes, texture sizes, compute sizes), and GX binds only what a shader declares. A shader that declares more than the adapter allows (D3D10 allows 128 shader resource views a stage) cannot be drawn: WebGPU rejects its bind group layout |
| virgl: tessellation evaluation without a control shader, tessellation followed by a geometry shader, image size queries, indirect draws with a count buffer, GLES 3.2, shader stencil export, points and lines wider than 1 pixel | Not offered or not handled (`shader_stencil_export` is not declared, and WGSL has no stencil output; the declared point size and line width ranges are 1, as WebGPU draws) |
| virgl: GL state not applied | Two-sided lighting (the rasterizer's `light_twoside`, back colors). Blend logic ops: drawn as plain blending (warned); WebGPU has none. The restart index and enable of `DRAW_VBO`: strips restart at the index format's all-ones value whatever the guest asks, the only restart WebGPU and D3D10 have; 8-bit indices are widened to 16-bit, 0xFF becoming 0xFFFF when restart is on. Non-seamless cube map filtering: `seamless_cube_map` is declared and the sampler's seamless bit ignored, as WebGPU's cube maps are always seamless; the difference shows along face edges |
| virgl commands | Not handled (warned once): `TRANSFER3D`, `COPY_TRANSFER3D`, `CLEAR_TEXTURE`, `GET_QUERY_RESULT_QBO`, `SET_ATOMIC_BUFFERS`, `GET_MEMORY_INFO`, `PIPE_RESOURCE_SET_TYPE`; the capset declares none of the capabilities Mesa wants before it sends them. Accepted without effect: `SET_POLYGON_STIPPLE`, `SET_CLIP_STATE` (user clip planes), `SET_MIN_SAMPLES` |
| virgl: `BLOB_MEM_HOST3D_GUEST`, mapping textures | Rejected (Mesa uses neither) |
| virtio-gpu 3D on Windows | Deferred; Windows guests get 3D from SVGA II. The known routes (the v86gl proxy with an x64 `v86gl.sys`, or a native WDDM driver) are in [Not done and deferred](gpu-devices.md#not-done-and-deferred) |
| Levels and the WebGPU adapter | A level is chosen by whether a renderer exists, not by the adapter's features or limits; a weaker adapter is never refused a level ([Not done and deferred](gpu-devices.md#not-done-and-deferred)) |
| Venus (Vulkan 1.1 on WebGPU) | Not offered: geometry and tessellation shaders, texel buffers (no format has the features), linear tiling, sparse resources, pipeline statistics queries, polygon modes other than fill, indirect triangle fans, adjacency, sampler LOD bias and border colors (clamped to the edge), line width (the pipeline's), dma-buf export (so no zero-copy WSI; G-43 imports), stores and atomics in the vertex stage (`vertexPipelineStoresAndAtomics`: WebGPU has no writable storage there; transform feedback is the extension, G-45). A draw whose pipeline's attachments are not its pass's (which WebGPU would answer by dropping the whole batch) is skipped, warned. With G-45 to G-47, ANGLE on it offers OpenGL ES 3.0. Not tested: specialization constants (naga's GLSL front end folds them, so the test shaders have none) |

## Known issues (Mesa's svga on Linux, `tests/x64/gltest.c`)

At level `dx11-full`, 31 of the 34 cases match llvmpipe (at `dx11`, 30: see
`flat-indexed-strip`). The ones that do not:

| Case | What happens |
| --- | --- |
| `fan-lines-points` | Points (which Mesa's svga expands with its own geometry shader) come out mirrored vertically; lines and the fan are right |
| `flat-indexed-strip` (`dx11` and below only) | These levels do not declare `DX_PROVOKING_VERTEX`, so Mesa converts the indices for GL's last provoking vertex itself, and its conversion of a strip with a restart makes a triangle of the restart index; `dx11-full` declares it and GX reorders |
| `rect-buffer-integer-textures` | The rectangle texture's coordinate scale is not among the constants Mesa uploads (its extra constants hold only the buffer texture's size), so the rectangle reads its first texel |
| `compute-buffer` | Mesa bakes the grid size into the compute shader's immediates (`key.cs.grid_size`); the shader it sends has 0 for `gl_NumWorkGroups` |

The last two are in what Mesa sends, not in how GX runs it. On virtio-gpu
(virgl) all 34 cases match.
